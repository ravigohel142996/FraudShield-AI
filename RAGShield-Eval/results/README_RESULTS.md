# results/ — artefact contract

Everything in this directory is generated by `src/evaluation_runner.py`. Nothing is
hand-edited. If you find yourself editing a file here to make a number look right, the
correct action is to fix the grader and re-run.

## Directory layout

```
results/
├── README_RESULTS.md          # this file
├── validation/                # PIPELINE VALIDATION — not model results
│   ├── raw_outputs.jsonl
│   ├── scores.csv
│   ├── summary.json
│   ├── per_task.json
│   ├── experiment_manifest.json
│   ├── report.md
│   └── dashboard_data.json
└── <live run>/                # created by `python -m src.runner run --live`
```

## The flag that governs interpretation

`summary.json` and `experiment_manifest.json` both carry
`counts_as_model_experiment: true|false`.

* `true` — every response came from a live provider call; the numbers are model results.
* `false` — the run used the offline deterministic stub; the numbers describe the stub, not
  a model. The dashboard and `report.md` render a red banner and refuse to present them as
  findings. **Do not cite these numbers.**

## `raw_outputs.jsonl`

One JSON object per attempted run — including API errors and empty responses, which are
never removed. Key fields:

| Field | Meaning |
|---|---|
| `run_label`, `started_utc` | run identity and start time (UTC, ISO-8601) |
| `task_id`, `task_category`, `task_difficulty`, `track` | what was run |
| `provider`, `model_id` | provider name and the **exact** model string sent to the API |
| `provider_class` | `llm_api` or `pipeline_validation_stub` |
| `repetition`, `temperature`, `max_output_tokens` | sampling settings |
| `prompt_sha256`, `system_prompt_sha256`, `user_prompt_sha256` | exact-prompt identity |
| `policy_version` | version of `config/policy.yaml` in force |
| `prompt_doc_ids` | documents actually placed in the context (post-authorization) |
| `retrieval_trace` | ranked candidates, `authorization_decisions`, `excluded_doc_ids`, `exclusions` |
| `response_text` | the model's output, verbatim, unedited |
| `usage` | input/output tokens, latency, attempt count |
| `estimated_cost_usd`, `cost_label` | estimate from the static price table, not a bill |
| `status` | `graded` \| `api_error` \| `empty_response` |
| `counts_as_scored` | whether this record may enter a metric denominator |
| `grading` | `task_passed`, `failed_checks`, per-check evidence, `critical_security_failure` |
| `leaked_canaries` | protected synthetic markers found in the response |
| `error` | `{type, message, http_status}` for API failures |

## `scores.csv`

One row per run, flattened for spreadsheets: task, model, repetition, status, task_passed,
critical flag, failed checks, canaries, prompt/excluded doc ids, tokens, latency, estimated
cost, prompt hash, timestamp.

## `summary.json`

Per model: `metrics` (each with numerator/denominator/status), `weighted` composite,
`per_task` breakdown, plus run counts and the preflight estimate.

## `experiment_manifest.json`

Reproducibility record: benchmark and policy versions and hashes, per-task definition hashes,
git commit, worktree cleanliness, platform/Python, run settings, counts, cost estimate, and
the `counts_as_model_experiment` flag.

## What must never appear in this directory

* A real API key, token or password (the ZIP builder scans for these).
* Real customer or personal data — the corpus is synthetic by design.
* Hand-written numbers. If a result is not produced by a run, it does not belong here.
